# Кабинеты DAM ALEM: рабочий процесс

Владелец и оператор входят через `/partner/dam-alem` со своими учётными данными.
Владелец управляет продажами, расходами, зарплатой, сотрудниками и настройками.
Оператор работает с заказами, составом чека, стоп-листом и доставками. Финансовые
отчёты и настройки владельца остаются закрыты серверными проверками роли.

## Доставки

Новый раздел показывает активные доставки только DAM ALEM в трёх группах:
до передачи, ожидание курьера, у курьера. У каждого заказа видны адрес,
назначенный курьер, телефон и остаток оплаты. Кнопка открывает исходный заказ.
Обновление каждые пять секунд; при ошибке остаётся предыдущий список и появляется
сообщение об ошибке. Повторный запрос доступен вручную.

Курьер работает в существующем `/cabinet/courier` через личный аккаунт Sortirovka24.
Доступ требует одобренной заявки `/delivery/courier`. Учётная запись оператора
не предоставляет доступ курьера. Панель курьеров парка с PIN относится к другому модулю.
При статусе «Готов» заказ поступает в существующую систему диспетчеризации.
Ручное назначение курьера и новый способ приёма платежей в этом изменении не добавлялись.

В кабинете курьера автообновление больше не перезаписывает телефон и транспорт
во время редактирования. Активная доставка обновляется даже вне линии.
Повторное нажатие смены статуса блокируется до окончания запроса; для еды
показывается номер заказа, а не внутренний номер доставки.

## Проверки и ограничения

Backend: 30 тестов операций, бизнес-кабинета и процесса заказа, включая новый
тест фильтрации доставок и отказа неавторизованному запросу.
Frontend: TypeScript, ESLint, сборка mobile, статический RU/KZ аудит.
Браузерные проверки используют тестовые API и ширины 320/390/768/1440.
Они не подтверждают реальную отправку Telegram, GPS, реальные платежи или деплой.

Результат браузерных проверок: 60 сценариев кабинетов и 4 проверки черновика курьера — успешно.
