# Кабинет DAM ALEM

Вход: `/partner/dam-alem`. По умолчанию открывается «Сегодня». Администратор портала также открывает кабинет из раздела DAM ALEM общей админки.

## Пять разделов владельца

1. **Сегодня.** Рабочая очередь за все дни, первые восемь ожидающих заказов, число заказов без отметки оплаты, ошибки уведомлений. Денежные показатели относятся к сегодняшней дате Караганды. Обновление раз в 15 секунд, пока вкладка видима.
2. **Заказы.** Поиск, статусы, оплата, адрес, заметки, история и уведомления. В завершённом заказе можно дополнительно подтвердить позднее получение оплаты. Полученную оплату нельзя стереть сменой статуса обратно на «ожидается».
3. **Продажи и расходы.** Сегодня, последние 7/30 дней либо свой период до 367 дней. Выгрузка CSV для Excel, популярные блюда, средний чек, бонусы, промокоды, поступления по способам оплаты, расходы и полные возвраты отменённых заказов.
4. **Меню и акции.** Блюда, категории, опции, баннеры и быстрые переключатели доступности. Уже принятые заказы переключение доступности не изменяет; сервер проверяет доступность при новом оформлении.
5. **Настройки.** Заведение, доставка и прочие параметры, Telegram, сотрудники. FrontPad по-прежнему подключается администратором портала.

## Как читать суммы

- Продажи считаются по дате завершения заказа (`completed_at`) и итоговой сумме после скидок.
- Поступления считаются по дате ручного подтверждения оплаты (`paid_at`). Это отметка сотрудника, а не автоматическая банковская сверка.
- Возвраты относятся к выбранной дате фактического возврата. Интерфейс записывает полный возврат сегодняшним днём. Запись доступна только для отменённого оплаченного заказа и не переводит деньги клиенту.
- Расходы относятся к указанной дате. Сумма положительная, точность до копеек/тиынов. Исправленная запись остаётся в истории с причиной и больше не участвует в расчёте. Для изменения суммы исключите ошибочную запись и внесите правильную.
- Денежная разница = поступления − отмеченные возвраты − внесённые расходы. Она **не является чистой прибылью**: автоматического учёта запасов, себестоимости и обязательств нет.
- Популярность блюд определяется по завершённым заказам, сумма строк — до скидок на весь заказ. Подарки имеют нулевую сумму. Промоскидка сохраняется при новых заказах из проверенного сервером расчёта.
- У старых заказов отсутствуют точные даты оплаты/завершения. Такие суммы не приписываются дате создания: отчёт показывает количество записей без дат. Старые промоскидки тоже не восстанавливаются из свободного комментария.

## Сотрудники и безопасность

Владелец открывает «Настройки → Сотрудники», вводит имя, email и пароль минимум 10 символов. Создаётся **оператор**, а не второй владелец. Пароль хранится только в виде bcrypt-хеша; передайте его сотруднику лично. В кабинете уже есть смена собственного пароля.

Оператору доступны «Сегодня» без финансовой сводки, «Заказы» и «Доступность блюд». Он не может смотреть отчёты, вносить расходы/возвраты, читать Telegram-настройки, менять цены через прежний общий API или управлять сотрудниками. Проверка роли идёт по активной записи БД на каждом запросе: подставленная/устаревшая роль в JWT не повышает права. Отключённый оператор теряет доступ и с ранее выданным токеном.

Существующие учётные записи без новой роли сохраняют прежние полномочия владельца. Первичный доступ владельца создаётся администратором портала через существующую форму «Доступ партнёра»; это обновление не задаёт дефолтный пароль и не создаёт живые учётные записи автоматически. Владелец не может отключить владельца из списка сотрудников.

## Технические примечания для выпуска

Новые таблицы: `food_expenses`, `food_refunds`. Новые nullable-поля: `partner_credentials.access_role`; `food_orders.paid_at`, `completed_at`, `cancelled_at`, `promo_discount_amount`. Стандартная инициализация приложения добавляет поля и создаёт таблицы. Выпускать frontend/backend вместе, предварительно сохранив резервную копию БД. После обновления проверить доступ владельца, создание тестового оператора и тестовый заказ.

Создание расхода имеет UUID операции: повтор того же запроса не создаёт дубликат, а изменение данных с тем же UUID отклоняется. Полный возврат уникален по номеру заказа. Финансовые исправления не удаляют записи без следа. Расчёты используют Decimal; дни отчёта соответствуют UTC+5 (Караганда).

Проверки находятся в `tests/test_dam_business.py`, `tests/test_dam_operations.py`, `tests/test_food_order_security.py`; браузерные — `e2e/dam-business.spec.ts`, `e2e/dam-operations.spec.ts`. Запуск браузерных проверок: `node node_modules/playwright/cli.js test --config playwright.dam-operations.config.ts`. В тестах используются отдельная БД и подменённые внешние API; живые расходы, сотрудники и сообщения не создаются.

CSV содержит итоговые показатели и расходы за выбранный период; текстовые ячейки защищены от выполнения формул при открытии в таблицах.
