# Полезный справочник

## Что видит посетитель

1. Постоянный блок экстренной помощи: 112, 101, 102, 103, 104. Он работает и при ошибке загрузки API.
2. Переходы к участковым и транспорту, если эти модули включены.
3. Поиск по названию, адресу, описанию и телефону. Все слова запроса должны совпасть; форматирование номера не мешает поиску. Запрос и категория сохраняются в URL.
4. Только заполненные категории и готовые местные контакты. Нестандартные категории больше не теряются.

Источник экстренных номеров: https://www.gov.kz/situations/729/1519?lang=ru (проверено 13 сентября 2026 года). 101 — пожарные и спасатели; 104 — аварийная газовая служба. Старые неверные подписи исправлены в общих переводах RU/KZ и в заготовке данных.

## Как заполнить карточку

В «Админка → Справочник» нажмите «Добавить». Укажите название, категорию, с какими вопросами обращаться, точный адрес и подтверждённый график. Телефон, WhatsApp, сайт и карта заполняются отдельно. Не объединяйте несколько номеров в одном поле; добавочный номер можно пояснить в описании.

Сохранение черновика не публикует карточку. Для публикации нужны название, категория, источник, дата реальной проверки и телефон или сайт. Источником должна быть страница организации или государственного органа, подтверждающая данные. Наличие ссылки само по себе не доказывает достоверность: редактор проверяет содержание.

Дата проверки не обновляется автоматически. При изменении контактов повторно проверьте их. Пустые часы не заменяются вымышленным «круглосуточно». Кнопки не появляются без корректного адреса ссылки или номера. Общее название «Прочее» доступно для записей вне основных категорий.

Фильтр «Требуют проверки» помогает разобрать старые записи. Неполные записи остаются в базе и админке, но не показываются жителям. Сохраните такую запись черновиком либо заполните и опубликуйте. Республиканские экстренные номера дублировать не нужно: карточки-дубликаты скрываются в публичном списке.

## Найденное в действующих данных

При чтении публичного API 13 сентября обнаружены пять записей: четыре без названий и одна с тестовым содержимым. Их данные на сервере не изменялись. Заготовка `mock_data/directory_entries.json` очищена от вымышленных местных организаций и содержит только подтверждённые экстренные номера. Она не предназначена для перезаписи действующей базы.

## Обновление сервера

Нужно обновить frontend и backend вместе. Добавлены nullable-поля `opening_hours`, `website`, `map_url`, `whatsapp`, `source_url`, `verified_at`, `is_published`; JSON-описание модели также обновлено. Существующий механизм инициализации БД добавляет отсутствующие поля. Перед выпуском проверьте журнал добавления колонок; старые записи не удаляются и не перезаписываются. Публичные GET-запросы не возвращают черновики и записи без названия, источника или даты. Авторизованная админка получает полный список. Запись защищена проверкой администратора.

Новый frontend с прежним backend покажет экстренные номера и пустой местный каталог, поскольку у прежнего API нет полей проверки. Не публикуйте эти версии по отдельности.

## Проверки

- `node node_modules/typescript/bin/tsc -b`
- `node node_modules/vite/bin/vite.js build --mode mobile`
- `node node_modules/playwright/cli.js test --config playwright.directory.config.ts`
- `python -m pytest tests/test_directory_entries.py --noconftest -q` из backend с его зависимостями.

Браузерные сценарии используют тестовые API-ответы и размеры 320, 390, 768, 1440 px, включая тёмную тему и увеличенный шрифт. По умолчанию проверяется `dist`; переменная `DIRECTORY_BUILD_DIR` позволяет указать другой каталог сборки. Серверный тест использует SQLite в памяти, проверяет доступ к черновикам, права записи, валидацию и сохранение новых полей. Реальные звонки, сообщения и публикация на сервер не выполняются.
