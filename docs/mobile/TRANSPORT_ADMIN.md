# Автобусы: заполнение и проверка

## Что изменено

Посетитель ищет автобус по номеру или названию остановки, выбирает маршрут, направление и день недели. Выбранные маршрут, направление, остановка и день сохраняются в URL. На телефоне после выбора автобуса страница переходит к его карточке.

У прямого и обратного направлений собственные списки остановок. Обратное направление не вычисляется разворотом прямого. Расписание относится **к отправлению от первой остановки выбранного направления**. Для промежуточной остановки страница не рассчитывает прибытие и явно поясняет это.

Нет индикаторов «На линии» / «Не работает», вычисляемых по часам пользователя. GPS-подключение и время прибытия в реальном времени не реализованы. Предвыбранный день недели определяется по времени Караганды (`Asia/Almaty`), а не часовому поясу устройства. В праздники нужно сверяться с перевозчиком; примечание можно добавить в карточку.

## Проверка прежних данных

13 сентября 2026 года публичный API содержал четыре маршрута: 27, 42, 69, 118, и 22 остановки. Названия, времена и описания совпадают с демонстрационными заготовками проекта. У записей не было источника расписания или даты проверки. Эти сведения нельзя считать подтверждёнными маршрутами Сортировки.

Исследованы официальные источники:

- https://karaganda.onay.kz/ru — официальный сайт ONAY! Караганда, ссылка доступна посетителю.
- https://www.gov.kz/memleket/entities/otdel-transporta-karagandy?lang=ru — отдел пассажирского транспорта города.

Подтверждённое актуальное расписание именно этих четырёх заготовок не получено. Старые номера, конечные и часы не перенесены в новый публичный каталог как достоверные. Данные действующей базы не удалялись и не исправлялись автоматически. Заготовки `mock_data/bus_routes.json` помечены неактивными, чтобы новые установки не публиковали их по умолчанию.

## Как заполнить

1. Откройте **Админка → Район и службы → Автобусы**.
2. Добавьте автобус или исправьте существующую запись. Укажите реальный номер и название маршрута.
3. В «Прямое направление» запишите все остановки по порядку, каждая с новой строки. Первая — место отправления.
4. Отдельно заполните обратное направление. Не копируйте список автоматически без сверки.
5. Для каждого направления выберите Пн–Пт, субботу или воскресенье. Заполните один вариант:
   - точные отправления в формате `06:10, 06:40, 07:15`;
   - первый рейс, последний рейс и опубликованный интервал;
   - отметку «В этот день рейсов нет», если это подтверждено.
6. Если расписание неизвестно, оставьте поля пустыми. Это означает «уточняется», а не «не ходит». Не рассчитывайте точные отправления из интервала.
7. Укажите страницу перевозчика / официальный документ и дату фактической проверки. Не используйте общую ссылку как подтверждение часов, если на ней их нет.
8. Сохраните черновик или включите «Опубликовать после проверки». Публикация требует источник, дату и минимум две остановки хотя бы одного направления. Незаполненное второе направление честно отмечается как неизвестное.

Старые остановки доступны внутри старой карточки только для сверки. Новые остановки и расписание сохраняются одним запросом вместе с автобусом в `journey_json`, поэтому не возникает частично обновлённого направления.

Снятие отметки публикации скрывает автобус; запись сохраняется. В блоке «Изменения и объявления» можно добавить сообщение для одного маршрута или всех. Общие сообщения показываются один раз. По окончании изменения снимите «Показывать».

## Выпуск

Frontend и backend выпускаются вместе. В `bus_routes` добавлены nullable-поля `journey_json` (Text), `source_url`, `verified_at`, `map_url`. JSON-описание модели обновлено. Существующий механизм инициализации БД добавляет отсутствующие поля; проверьте журнал его работы при выпуске. Старые колонки времени и таблица `bus_stops` сохраняются.

Публичный API маршрутов не возвращает неподтверждённые записи; администратор видит полный список. Запись маршрутов защищена проверкой администратора, расписания проверяются на сервере. Новый frontend со старым API покажет состояние проверки и ссылку ONAY!, поскольку старый API ещё не отдаёт новые поля.

## Проверки

- `node node_modules/typescript/bin/tsc -b` из frontend.
- `node node_modules/vite/bin/vite.js build --mode mobile`.
- `node node_modules/playwright/cli.js test --config playwright.transport.config.ts`. По умолчанию используется `dist`, другой каталог — через `TRANSPORT_BUILD_DIR`.
- `python -m pytest tests/test_transport_schedule.py --noconftest -q` из backend с зависимостями.

Браузерные тесты используют явно тестовые маршруты, размеры 320, 390, 768, 1440 px, тёмную тему и крупный шрифт. Проверяются поиск, направления, остановки, дни, ночной интервал, пустое расписание, сохранение и публикация. Серверные тесты используют SQLite в памяти, проверяют права, сохранение обоих направлений, скрытие старых записей и отклонение неверного времени. Тестовые данные не отправляются на действующий сайт.
