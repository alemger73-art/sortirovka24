# DAM ALEM: кабинет заказов и Telegram

Актуальные изменения расчётов, редактирования чека, возвратов и защиты Telegram описаны в [исправлениях аудита от 19 сентября 2026](DAM_ALEM_AUDIT_FIXES.md). Они заменяют приведённые ниже исторические ограничения первого выпуска.

Кабинет: `/partner/dam-alem?section=orders`. Используется существующий вход партнёра DAM ALEM. Администратор портала открывает тот же раздел через админку DAM ALEM.

## Работа оператора

- По умолчанию открывается «Сегодня», заказы — отдельная вкладка. По умолчанию показаны заказы в работе; «Все заказы» включает архив. Есть серверный поиск по номеру, имени, телефону и адресу и постраничная загрузка без ограничения последними 200 заказами.
- Порядок: новый → принят → готовится → готов к выдаче → в доставке → завершён. Самовывоз из «Готов к выдаче» завершается кнопкой «Выдан клиенту».
- Статус «В доставке» оператор ставит при фактической передаче заказа. Он не означает автоматического назначения курьера или GPS-слежения. Прежняя автоматическая отправка персональных данных DAM ALEM в отдельный Telegram курьеров не используется.
- Получение оплаты отмечается отдельно и вручную после проверки денег. Это не банковская проверка и не списание. Отмена требует причины и не выполняет банковский возврат.
- Можно уточнить адрес и оставить внутреннюю заметку. Состав, цены и сумма принятого заказа зафиксированы: для замены оформляется новый заказ, прежний отменяется с причиной. Это сохраняет согласованность бонусов и расчёта стоимости.
- Действия записываются в журнал с идентификатором текущей сессии. При общих учётных данных журнал не различает сотрудников. Индивидуальные операторы и разграничение прав теперь доступны в «Настройки → Сотрудники»; подробности в DAM_ALEM_CABINET.md.
- При конфликте версий изменение отклоняется: обновите карточку, проверьте актуальное состояние и повторите действие. Открытые формы не перезаписываются автообновлением.

## Telegram

1. Создайте бота через BotFather, добавьте его в рабочий канал администратором с правом публикации.
2. В кабинете откройте Telegram. Введите токен и ID канала `-100…` либо публичное `@имя`. Можно использовать группу.
3. Сохраните и нажмите «Отправить тест в сохранённый канал». Это единственная кнопка, которая отправляет тестовое сообщение. Сохранение при включении проверяет бота и права через чтение API.
4. Включите «Отправлять уведомления…», при необходимости включите изменения статусов, сохраните.

Состав уведомления: **номер заказа, текущий статус и ссылка на кабинет**. Имя, телефон, адрес, состав, сумма, комментарий и заметки не отправляются. Ссылка требует входа. Формирование кнопки требует серверной переменной `PUBLIC_FRONTEND_URL` с HTTPS-адресом сайта (допустим совместимый `FRONTEND_URL`). Если адрес не задан, текст предлагает открыть кабинет вручную.

Документация Telegram: https://core.telegram.org/bots/api#sendmessage и https://core.telegram.org/bots/api#getchatmember .

Настройки изначально выключены. Они не наследуют общий Telegram-канал портала или переменные `TELEGRAM_*_FOOD`. Ключ хранится в отдельной таблице, зашифрован Fernet; API никогда не возвращает сам ключ. Используется стабильный серверный `FOOD_SECRETS_KEY`, если задан, иначе секрет подписи JWT. После замены ключа шифрования токен нужно ввести заново. На production секрет должен сохраняться между деплоями. Логи httpx маскируют токен бота.

## Доставка уведомлений

Заказ и запись очереди сохраняются в одной транзакции. Ошибка Telegram не отменяет заказ. Фоновый обработчик проверяет очередь примерно каждые 10 секунд, только после инициализации БД. Задания сохраняются при перезапуске сервера. Включение отправки начинает обработку накопленной очереди, включая более ранние новые заказы.

Подтверждённые ошибки повторяются с задержкой, максимум пять попыток. При тайм-ауте/обрыве после отправки результат помечается «не подтверждён»: автоматического повтора нет, поскольку Telegram не поддерживает ключ идемпотентности для sendMessage. Проверьте канал перед ручным повтором. Завершённые уведомления повторить через API нельзя. Снятие флага уведомлений приостанавливает очередь; уже выполняющийся запрос может завершиться.

Старые заказы не удаляются. Их журнал начинается с первого изменения после обновления. Автоматический слепой повтор создания заказа на витрине убран: ответ сети может потеряться уже после сохранения заказа. Полная идемпотентность повторной ручной отправки корзины этим изменением не вводится.

## Данные и выпуск

Добавлены таблицы `food_operations_settings`, `food_order_events`; поля `food_orders.version`, `operator_note`, `cancellation_reason` nullable для совместимости. Существующая инициализация БД создаёт таблицы и добавляет столбцы. Выпускать frontend/backend вместе после резервной копии БД.

Кабинет отбирает только ID заведений с названием DAM ALEM / Алем Фуд и известные старые заказы без restaurant_id. Другие рестораны не подмешиваются. Партнёрские запросы к прежнему общему food_orders API перенаправляются сообщением в новый кабинет; публичное создание заказа сохранено.

Проверено изолированно: права доступа, чужой restaurant_id даже с подставленным названием, конфликт версий, допустимые переходы, самовывоз, причина отмены, запрет изменения цены, очередь при создании, ошибки/тайм-ауты Telegram, отсутствие токена в ответе. Отправка в тестах подменена. Браузерные тесты: `playwright.dam-operations.config.ts`; API: `tests/test_dam_operations.py`. Реальное подключение к каналу проверяется после внесения настроек, без передачи секретов в переписку.
