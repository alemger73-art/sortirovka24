# Общая касса DÄM ALEM

Одна физическая касса бизнеса, независимо от числа операторов и их личных смен.
Владелец открывает **Финансы → Общая касса**, оператор — **Общая касса**.

## Начало работы

Владелец один раз пересчитывает наличные и сохраняет фактический начальный остаток.
До этого остаток неизвестен, а исторические оплаты не превращаются в поступления
новой кассы. Система не записывает начальный остаток автоматически.

После активации:

- Подтверждение наличной оплаты на месте увеличивает кассу.
- Kaspi/Halyk не изменяют наличный остаток.
- Наличные, полученные курьером, остаются у курьера. Касса увеличивается только
  после подтверждения передачи денег сотрудником.
- Отмеченный наличный возврат уменьшает кассу в момент оформления.
- Статус выполнения заказа сам по себе денег не перемещает.

## Ручные операции

- **Расход из кассы**: сумма, получатель, назначение, категория. Одновременно
  создаёт один FoodExpense в существующих финансах. Повторно записывать не надо.
- **Выдать без нового расхода**: изъятие владельцем, оплата уже учтённого расхода
  или зарплаты. Не создаёт второй финансовый расход.
- **Внести деньги**: увеличивает кассу, не является выручкой.
- **Разница по пересчёту**: доступна владельцу, подписанная сумма и обязательное
  основание; история исходных движений сохраняется.

Старые формы расходов, зарплаты и вознаграждений не сообщают, из какого источника
они оплачены. Поэтому они сами по себе не списывают наличные: фактическую выдачу
нужно оформить через «Выдать без нового расхода». Отмена бухгалтерского расхода
тоже не доказывает возврат денег; реальное возвращение оформляется внесением.

## Защита и история

Оператору нужна открытая личная смена; владельцу смена не требуется. Проверки
роли, действующего доступа и принадлежности DAM выполняются на backend.
Журнал содержит автора, время, получателя, назначение и связь со сменой/заказом/
расходом. Смена оператора журнал не обнуляет. UI показывает последние 100 записей,
баланс — сумму всех записей. Удаление и редактирование движений не предусмотрены.

Повтор запроса использует тот же UUID. PostgreSQL transaction advisory lock
сериализует движения общей кассы и проверку достаточности средств. Деньги хранятся
в NUMERIC(14,2). События оплат и передачи денег записываются вместе с движением
кассы в одной транзакции. Отрицательный остаток после реально оформленного
возврата показывается явно и требует сверки, возврат при этом не скрывается.

## Схема и проверки

Единственная новая таблица — `food_cash_entries`, журнал фактических движений.
Она ссылается на существующие заказы, смены и расходы. Для версионированных БД
есть миграция `dam20260930_shared_cashbox`. Для существующей legacy production БД
используется проверенный additive SQL `scripts/releases/dam-cashbox-20260928.sql`.
Он не переписывает историю и не выставляет фиктивную Alembic revision.

Проверки: PostgreSQL + SQLite (собственные временные схемы), API ролей, повторная
миграция, двойной запрос, конкурентное списание, оплата/возврат, передача курьера.
Браузерные проверки UI используют контролируемые ответы API на 320/390/1440 px;
проверки сохранения и финансовых связей отдельно проходят на реальной БД.
