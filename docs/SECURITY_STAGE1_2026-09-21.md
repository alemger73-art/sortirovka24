# Первый этап исправлений безопасности — 21 сентября 2026

Изменения подготовлены локально. На production не отправлены. Новых таблиц и миграций в этом пакете нет.

## Что изменено

- AUD-01: удаление, переименование и перечисление объектов хранилища разрешены только администратору; перед вызовом Cloudinary проверяется доступ. Публичные загрузки и чтение фотографий сохранены. Новые загрузки получают серверный случайный ключ, перезапись существующего объекта запрещена. Полноценная модель владельца каждого исторического файла этим не создаётся.
- AUD-02/03: кабинет, общий `/auth/me`, приватные настройки и определение пользователя для бонусов используют одну проверку активной сессии, срока, состояния пользователя и текущей роли из базы. Блокировка/удаление через account-admin отзывает сессии; последующая разблокировка их не восстанавливает. Выход через обе реализации авторизации отзывает сессию. OIDC-вход теперь также создаёт запись `user_sessions`.
- AUD-04: публичная отправка объявлений, вакансий и недвижимости всегда создаёт `pending`. Клиент не назначает одобрение, чужого владельца, продвижение, число просмотров и служебные даты. Обычный процесс одобрения в админке сохранён.
- AUD-05: списки, `/all` и прямой ID новости скрывают неопубликованное; объявления, вакансии и недвижимость скрывают неактивные/неодобренные записи. Оба существующих статуса `approved`/`published` разрешены. `/user_preferences/all` возвращает только настройки текущего пользователя.
- AUD-09: отсутствует пароль администратора по умолчанию. Без `ADMIN_PASSWORD` первый администратор не создаётся. Перезапуск не включает отключённую запись. Пароли существующих записей не меняются, кроме уже существующего явно включаемого `ADMIN_FORCE_RESET`.
- AUD-18, частично: тело загрузки читается с ограничением объёма по мере поступления, включая запросы без Content-Length. Полный аудит форматов загружаемых файлов остаётся отдельной задачей.

## Совместимость и ограничения

- Старые JWT без серверной сессии больше не принимаются. Пользователям старого OIDC-входа потребуется войти заново. Существующие активные account-сессии продолжают работать.
- Старые публичные файлы не удалены и не перемещены. Приватность уже загруженных документов курьеров (AUD-06) этим пакетом НЕ исправлена. Нужны отдельное приватное хранение и проверка фактических ACL Cloudinary.
